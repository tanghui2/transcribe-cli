## 逐屏发现与修改

### 屏幕 03 · 纪要视图（第一版是纯文字表格）

**看到什么**：一整屏只有标题 + 段落列表，没有任何图形。检测器直接判"连续多屏只有文字和框"。

**改法**：加"要点在原片中的分布"柱状图 —— 横轴是时间位置，柱高是该要点对应的话在原片里占多长。这个图回答的是用户真正会问的问题："这 8 条要点分别在讲什么位置的什么内容"，纯文字列表回答不了。

### 屏幕 04 · 导出视图（第一版是纯文件表）

**看到什么**：六个文件一行行列出来，但用户看不出体积差异从哪来。

**改法**：加"输出体积构成"横向条形图，并给出一句结论 —— "JSON 占 58%，是字幕文本的 7 倍"。这条信息直接决定用户要不要勾选 JSON 选项（带词级时间戳，体积代价 7 倍）。

### 屏幕 07 / 08 · 环境自检（第一版是纯数据表）

**看到什么**：两屏都只有表格，且看不出"整体行不行"。

**改法**：加健康度环形图 + 一句人话结论：
- 通过屏：100%，"共检查 14 项，全部通过…全程不产生任何网络请求"
- 失败屏：78%，"GPU 可见但 cudnn 运行库不在 PATH，模型尚未下载。已自动降级到 CPU 推理：速度约为 GPU 的十分之一，3 小时素材要跑一整天"

另加"各项检测耗时"横条 —— 让用户知道自检不是卡住了，1.8 秒就查完了。

### 屏幕 06 · 首次运行 · 模型下载引导

**看到什么**：状态带第一格是红色错误态"等待模型"。这不对 —— 模型没下载是**尚未开始**，不是**出错**。红色会让用户以为软件坏了。

**改法**：新增 `todo` 态（中性灰白 `#DDE3EA`），与 `err` 态（红 `#F3A79E`）严格区分。状态栏 LED 也从琥珀色改为灰色。这一处是语义修正，不是美化。

### 屏幕 07 / 08 · 状态带语义混用

**看到什么**：自检屏的状态带五格写着"CUDA / 模型 / Ollama / ffmpeg / 磁盘"，编号是 01–05，和转写屏的"01 解码 / 02 识别 / 03 纪要 / 04 翻译 / 05 导出"长得一样但完全不是一回事。同一排格子承载两种语义，用户会误以为自检也是流水线阶段。

**改法**：自检两屏的编号前缀从 `01` 改为 `组件 01`，明确这是组件检查而非流水线阶段。转写屏保持 `01 解码` 不变。

### 分布图刻度文字变形

**看到什么**：SVG 时间刻度（0:00 / 43:50 / 1:27:40…）被拉成横向宽扁的畸形字。

**根因**：SVG 用了 `preserveAspectRatio="none"` 做拉伸适配，viewBox 里的 `<text>` 跟着一起被拉伸。

**改法**：刻度从 SVG 里移出来，改成 HTML 的 flex 行。SVG 只画柱子和基线 —— 拉伸只影响几何形状是安全的，影响文字不安全。

## 交互（真实可点，非静态图）

- **标签页**：五个视图标签可点，`.on` 状态在标签与内容间切换
- **模型规格卡**：四张卡可点切换选中态，`✓` 标记跟随
- **波形条**：SVG 程序化生成，柱高按真实段落时长（17.6s / 4.1s / 3.0s / 3.9s…）推算，每个段落块对应一个字幕段
- **分布图**：SVG 程序化生成，8 条要点的位置与覆盖占比按真实段落推算
