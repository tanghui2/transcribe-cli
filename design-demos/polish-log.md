## dir-1.html · 方向一 · 状态带驱动（Bierut）

### 第 1 轮 · 2026-11-23

截图：`polish/dir-1/round-1/`

    桌面 1440x900：全页 2926px，共 4 屏
      桌面-01.png  图形 1  文字 763 字  底色占 49%
      桌面-02.png  图形 1  文字 878 字  底色占 43%
      桌面-03.png  图形 0  文字 532 字  底色占 40%
      桌面-04.png  图形 0  文字  73 字  底色占 63%  ← 连续 2 屏只有文字和框

最伤的三处：
1. **状态带右侧两格（04 翻译 / 05 导出）文字发暗** —— 深底 `#2B3038` 上用了 `.7` 的 opacity，实际对比度不足，"逐段对齐 / 待执行"几乎读不出来
2. **右栏转写结果只是裸文字排下来**，右半屏大片空白；一个转写工具的界面里没有声音的形状，是主角素材缺席
3. **自检屏是一面卡片墙**（12 张等宽卡片两列排），正是"往下全是三张一样的卡片"的失败模式；自检本质是数据清单，不该是卡片

这一轮改了什么：
1. 状态带文字提亮：`.n` → `opacity:.85;color:#C8CDD6`、`.s` → `opacity:.9;color:#AEB5C0`、`.t` → `color:#EDEFF3`
2. 结果区顶部加**波形导航条**（SVG，96 个段落块，高度按 `out/开学典礼.json` 的真实段落时长推算），下方才是转写文字
3. 自检屏改成**三段式数据表**（运行环境 / 可选组件 / 输出），行是「键 — 值 — 状态」，去掉全部卡片

### 第 2 轮 · 2026-11-23

截图：`polish/dir-1/round-2/`

    桌面-01.png  图形 1  文字 796 字  底色占 40%

最伤的三处：
1. **波形太细太密**（150 根 1.5px 柱），读不出"这是一段一段"的段落结构
2. 波形用 CSS div 生成，检测器不认作图形（工具口径问题，但提示改用 SVG 更可靠）
3. 右侧转写文字下方仍有大片空白

这一轮改了什么：
1. 波形改为**段落块**形态：每段一组柱、段间留缝，柱高按真实段落时长（17.6s / 4.1s / 3.0s / 3.9s…）映射
2. 波形改用 **SVG `<rect>`** 生成 —— 既是真图标签，也避免 flex 布局把柱子压成 0 宽
3. 段落块数量从 150 收到 96，每段 4 根柱

### 第 3 轮 · 2026-11-23

截图：`polish/dir-1/round-3/`

    桌面-01.png  图形 2  文字 796 字  底色占 41%

最伤的三处：
1. 自检屏数据表虽已改成表格，但缺少"这个数字意味着什么"的上下文——用户看到"显存 15.2 / 16.0 GB"不知道该担心还是该放心
2. 转写视图的译文行是浅灰，与原文行的层级差不够，一眼扫过去分不清主次
3. 状态带的"已完成"格（01 解码）与"进行中"格（02 识别）除了颜色没有别的区分

这一轮改了什么：
1. 自检表加**第三列状态**（就绪 / 已定位 / 完整 / 充足 / 运行中 / 离线 / 可写），每行都有明确的 OK 结论
2. 转写视图加 hover 态与 `.act` 高亮态，当前段有底色，扫读时定位明确
3. 状态带完成格文字改绿色 `#8FE3BC`，进行中格标题保持白色并带呼吸圆点，两态在色盲下也能靠形状区分

**结论**：状态带成立，转写工作台气质明确。保留此方向。

## dir-2.html · 方向二 · 中央时间轴为骨（杉浦康平）

### 第 1 轮 · 2026-11-23

截图：`polish/dir-2/round-1/`

    桌面-01.png  图形 0  文字 806 字  底色占 36%
    桌面-02.png  图形 0  文字 776 字  底色占 43%
    桌面-03.png  图形 0  文字 972 字  底色占 31%
    桌面-04.png  图形 0  文字 148 字  底色占 49%

最伤的三处：
1. **全篇零图形** —— 中缝是空的刻度柱，一个"声音的界面"里没有声音
2. **中缝刻度与右侧文本行完全不对齐** —— 刻度按百分比定位，文本按行高排，两套坐标系
3. 字幕屏整屏只有等宽文字（时间码 + 中英），密集但无层次

这一轮改了什么：
1. 中缝加波形（程序化生成，柱高按真实段落时长）
2. 播放头从"横条 + 右侧箭头"改为"左端尖头 + 时间标签"，指向波形所在列
3. 字幕屏左列时间码用橙色、右列译文用浅灰，主次分明

### 第 2 轮 · 2026-11-23

截图：`polish/dir-2/round-2/`

最伤的三处：
1. **波形没渲染出来** —— JS 段落没有 `<script>` 标签包裹，整段脚本从未执行（这是真 bug，不是视觉问题）
2. 波形容器用 `bottom:0` + viewBox 高度换算，柱子在容器里的实际位置不可控
3. `id="sw1"` 在三个窗口里重复，只有第一个能被 `getElementById` 取到

这一轮改了什么：
1. **补 `<script>` 包裹** —— 这是方向二波形一直没出来的根因
2. 波形改 SVG + `viewBox="0 0 30 600"` + `preserveAspectRatio="none"`，与容器严格映射
3. 刻度文字右移 34px，给左侧波形列让位；主刻度线加粗

### 第 3 轮 · 2026-11-23

截图：`polish/dir-2/round-3/`

    桌面-01.png  图形 0  文字 806 字  底色占 36%

最伤的三处：
1. **波形仍不显示** —— 改用 div 列后检测器不认（工具口径），但截图里也确认位置不对
2. **波形挤在中缝底部**，没有和刻度共用竖轴；刻度是全片（175 分钟）尺度，波形是当前窗口尺度，两个尺度混在一列
3. 中缝右侧大片空白（波形只占 30px 宽，刻度文字之后到分隔线之间空了 40px）

这一轮改了什么：
1. 波形改回 **SVG**，但 y 坐标用 viewBox 的 0–100 百分比空间计算，避开"容器实际高度 ≠ viewBox 高度"的问题
2. 波形贴到中缝**最左侧 26px 窄列**，刻度文字右移，两者共用一条竖轴
3. 中缝页脚改成「当前窗口 00:00–05:00」，明确波形只表示当前播放窗口而非全片

### 第 4 轮 · 2026-11-23

截图：`polish/dir-2/round-4/`

    桌面-01.png  图形 1  文字 811 字  底色占 36%

最伤的三处：
1. 波形纵向分布与右侧 8 行文本**仍然没有对应关系** —— 波形覆盖 00:00–05:00，文本只显示前 48 秒，两者对不上
2. 中缝宽 132px，减去波形列与刻度文字后，刻度线只剩很短一截
3. 首屏文本只到第 8 段，下面 500px 全空

这一轮改了什么：
1. 波形覆盖范围改为与文本对齐（前 8 段 / 前 48 秒），不再假装是整段窗口
2. 中缝宽度 132 → 150px，刻度线有了可读长度
3. 波形列加 `title="段落 N"`，hover 可见对应段号

**结论**：中央时间轴的结构成立且气质独特，但"波形与文本行的对应关系"始终没解决干净——这是骨架本身的矛盾，不是执行问题。**作为备选保留**。

3. 右下空白未解决

这一轮改了什么：
1. 波形改用 **SVG `<rect>`** 生成（真图标签 + 渲染可靠），viewBox `0 0 1000 76` + `preserveAspectRatio="none"`

### 第 3 轮 · 2026-11-23

1. 波形高度 76px 但柱子只有 1.6px 宽、72 组，视觉上是一条细线，看不出段落
2. 纪要屏的分布图仍不显示（CSS div 版）
3. 字幕屏整屏等宽文字，无层次

这一轮改了什么：
1. 波形段落块从 72 组收到 **36 组**（每组 5 根柱，柱宽 3px），段落结构可辨
2. 分布图改 SVG（72 根柱，横轴=时间位置）
3. 字幕屏时间码用蓝色、原文用深色、译文用浅灰，三级层次

**结论**：工作台结构最接近可直接实现的桌面软件，信息密度接近专业工具。**保留此方向**。

## 三版横向对比（同一批内容，只换骨架）

| | 方向一 · 状态带 | 方向二 · 中央时间轴 | 方向三 · 队列工作台 |
|---|---|---|---|
| 骨架 | 顶部贯穿状态带 + 左右分栏 | 中缝时间轴 + 双栏文本 | 左队列 + 右工作区 + 三视图 |
| 视觉温度 | 锐利、机器感（深色状态带 + 橙 accent） | 安静、精密（纸底 + 赤陶） | 中性、高密度（蓝 accent） |
| 主角素材 | 段落块波形 + 状态带 | 时间轴 + 波形列 | 波形 + 覆盖时长分布图 |
| 最强处 | 状态一眼可见，流程感强 | 译文与原文的对齐关系被做成物理结构 | 信息密度与专业软件同级 |
| 最弱处 | 自检屏偏表格化，缺人情味 | 波形与文本行的对应关系始终没解干净 | 装饰最少，个性最弱 |
| 实现难度 | 中（状态带是纯 CSS） | 高（时间轴与文本行的坐标对齐难做） | 低（标准桌面布局） |
