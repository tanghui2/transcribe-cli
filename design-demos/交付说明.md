## 三个方向

### 方向一 · 状态带驱动

**骨架**：顶部贯穿全宽的状态带（解码 → 识别 → 纪要 → 翻译 → 导出），同时是进度条和阶段导航；下方左右分栏（左：文件队列 + 参数；右：波形 + 结果）。

**form 来自内容的哪里**：转写是一条流水线，状态带就是这条流水线本身。

**胆量**：状态带做成实心色块，颜色随阶段推进变化（冷灰 → 橙 → 绿）。它不是一个细进度线，是这个软件的脸。

**特点**：流程感最强，用户永远知道"现在进行到第几步、下一步是什么"。

### 方向二 · 中央时间轴为骨

**骨架**：中缝是一条有刻度的宽栏，播放头是压在上面���实心块；左右分列原文与译文，中缝是时间。

**form 来自内容的哪里**：字幕的本质就是两段文字被一条时间锁住，这个界面把它做成物理结构。

**特点**：译文与原文的对齐关系是最直观的，学术气质，适合严肃的字幕工作流。

**已知问题**：波形与文本行的对应关系始终没解干净——刻度是全片尺度、波形是当前窗口尺度，两者混在一列。这是骨架本身的矛盾。

### 方向三 · 队列驱动的工作台

**骨架**：左侧任务队列（四列：文件 / 模型 / 任务 / 状态）＋ 右侧常驻工作区（转写 / 纪要 / 双语字幕三视图切换，共用同一时间轴）；转写设置是右侧滑出抽屉。

**form 来自内容的哪里**：这个工具的核心产出不是一段文字，而是同一段内容的三种形态（原文 / 纪要 / 译文），所以是视图切换而不是页面跳转。

**特点**：信息密度与专业软件同级，实现难度最低，是最接近可直接开发的方案。

## 三个方向的关系

| | 方向一 · 状态带 | 方向二 · 中央时间轴 | 方向三 · 队列工作台 |
|---|---|---|---|
| 骨架 | 顶部状态带 + 左右分栏 | 中缝时间轴 + 双栏文本 | 左队列 + 右工作区 + 抽屉 |
| 视觉温度 | 锐利、机器感 | 安静、精密、书卷气 | 中性、高密度、专业 |
| 主角素材 | 段落块波形 + 状态带 | 时间轴 + 波形列 | 波形 + 覆盖时长分布图 |
| 最强处 | 状态一眼可见，流程感强 | 对齐关系最直观 | 密度与专业软件同级 |
| 最弱处 | 自检屏偏表格化 | 波形与文本行对不齐 | 个性最弱，装饰最少 |
| 实现难度 | 中 | 高（坐标对齐难做） | **低（标准桌面布局）** |

**骨架相似度**：1↔2 = 0.28，1↔3 = 0.22，2↔3 = 0.39 —— 三版骨架互不重复。

## 三个未做的候选（备选）

- **MacWhisper 式**（真实参照）：首屏即产品正在工作的样子，把真实界面当主视觉。骨架与方向一的状态带主题重叠，作为备选。
- **电影感声波可视化**（轮盘抽到，web 第 8 条）：波形作为真实数据图像贯穿全界面。波形做主角的机制好，但纯波形 + 文本两段较常规。
- **田中一光几何平面构成**（轮盘 east 第 9 条）：用几何色块与分割线组织信息，不用圆角卡片。骨架有趣，但与"功能齐全"的信息密度要求有冲突。

## 打磨记录摘要

三版各过了 3–4 轮打磨环。最关键的三次修正：

1. **方向一**：自检屏原是 12 张等宽卡片墙 → 改成三段式数据表（键—值—状态），每行都有明确结论
2. **方向二**：JS 段落漏了 `<script>` 标签，波形从未渲染 → 补上（这是真 bug 不是视觉问题）
3. **方向三**：波形用 flex 分组时柱子被压成 0 宽 → 改用 SVG `<rect>`，渲染稳定且是真图标签
