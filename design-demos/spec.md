## 1 · 项目是什么

**transcribe-cli** 是一个本地音视频转写工具：把媒体文件丢进去，产出字幕（SRT/VTT）、纯文本、结构化 JSON、中文纪要、译文、时间轴对齐的双语字幕。

- 全部推理在本机完成（faster-whisper large-v3 + CUDA 加速 / 本地 Ollama）
- 零 API 成本，素材不出设备，断网可用
- 已发布为 GitHub 开源项目（github.com/tanghui2/transcribe-cli），有 16 个文件、MIT 许可、Release v0.1.0 附带 93.6MB 单文件 exe

**本阶段要做的事**：把现有的命令行工具，变成一个下载下来就能用、有完整可视化界面的桌面程序。

## 2 · 受众与场景

| | |
|---|---|
| **主受众** | 不想装 Python、不想记命令的普通用户 —— 教师、字幕译者、播客/短视频创作者、自媒体 |
| **次受众** | 懂技术的用户 wanting 批量处理、参数调优 |
| **典型场景 A** | 手上一段 2 小时课程录像，要字幕 + 中文纪要 + 英文译文 |
| **典型场景 B** | 一堆课程音频，要批量转成字幕 |
| **典型场景 C** | 给视频加双语字幕，译文要跟原文时间轴严格对齐 |
| **设备** | Windows 为主（exe 已验证），需支持 macOS / Linux |
| **语言** | 中文为主界面 |

## 3 · 核心信息（页面要讲清的）

按重要性排序：

1. **本地跑，零成本，素材不出机器** —— 这是产品最硬的差异点
2. **转写 → 纪要 → 翻译 → 字幕，一条链做完** —— 功能齐全的价值
3. **快** —— 175 分钟素材 27 分钟，6.4 倍实时
4. **字幕质量** —— 时间轴严格对齐、双语上下对照
5. **零门槛** —— 拖进来就行，不用装环境

---

## 4 · 情感基调

**专业、可靠、克制。**

不做活泼跳跃的消费级风格（那是小猫补光灯那一类），也不做冷冰冰的工程工具（Buzz 现在就是那样，用户评价"Functional rather than attractive"）。

这个工具的用户是拿着它干活的，要的是"这东西靠得住"。视觉上要有密度和秩序，但每一处都服务于操作，不炫技。

关键词：**内敛的密度 / 精确 / 可信赖 / 工具感**

## 5 · 必须暴露的功能（来自现有 CLI 能力，一个不能丢）

### 转写
- 拖放 / 选择音视频文件
- 模型选择（large-v3 / large-v3-turbo / medium / small）与模型目录
- 设备与精度（cuda / cpu；float16 / int8）
- 语言（自动检测 / 中文 / 英文 / …）
- beam size
- VAD 静音过滤开关
- 词级时间戳开关
- initial prompt（引导专有名词识别）

### 摘要
- 生成本地中文纪要（概要 / 要点 / 待办）
- Ollama 服务可用性检测与模型选择

### 翻译
- 目标语言
- 整段译文 / 逐段双语字幕两种模式

### 导出
- SRT / VTT / TXT / JSON / Markdown
- 输出目录选择
- 双语 SRT 导出

### 系统级
- 环境自检（CUDA、模型、Ollama、ffmpeg 状态）
- 实时进度（当前段落文字 + 百分比 + 实时倍速）
- 任务队列（多文件）
- 打开输出目录
- 复制内容到剪贴板

### 空/错/载入状态
- 首次使用：模型未下载 → 引导下载
- 无 GPU → CPU 模式提示
- Ollama 未启动 → 明确说明并只影响摘要/翻译
- 转写失败 → 错误归因（显存不足 / 模型缺失 / 格式不支持）
- 转写进行中 → 可取消

## 6 · 输出格式与尺寸（三个方向必须统一）

- 交付：单文件 HTML 原型，每个方向 1 个
- 画布：**1440 × 900**（桌面应用主窗口尺寸）
- 用 macOS / Windows 窗口外壳包裹（`assets/macos_window.jsx` 的思路，或等价的 HTML 实现）
- 截图：1440 宽整页 + 首屏
- 至少包含 3 个界面状态：主工作台 / 转写结果查看器 / 设置或导入

## 7 · 已知约束

- 项目**没有 logo、没有品牌色、没有字体规范**（新建项目，账本为空）
- 竞品 Buzz 的界面：89% 浅灰白底 + 纯黑字 + 单一橙色 accent，功能齐全但审美朴素
- MacWhisper €65 一次性买断，走精致路线但功能在 Pro 后面
- 现有项目已发布在 GitHub，界面设计要能对上 README 里承诺的能力，不能夸大
- 数字必须用实测值（6.4x 实时、175 分钟、5221 段、93.6MB），不编造

## 8 · 图片需求

**产品界面本身就是主角素材**（数字产品必须有 UI 截图）——三个方向的界面本身就是 UI。

需要的真实素材：
- 真实转写文本（`out/开学典礼.srt` 已有）

- 真实双语字幕对照（`out/开学典礼.English.srt` 已有）

**Logo**：项目无 logo。三个方向各自提出 logo/标记的处理方案（几何标记 / 纯文字 / 波形符号），在方向卡里写明。

## 9 · 三个方向的差异点（不许只换皮）
