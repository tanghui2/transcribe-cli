# 发布到 GitHub 指南

## 一句话版本

```bash
gh auth login          # 只需一次
python scripts/publish_release.py
```

第二条命令会做完：推源码 → 打 tag → 建 Release → 上传两个 zip。

---

## 前置条件

1. **已安装 gh**：本机已有 `C:\Program Files\GitHub CLI\gh.exe`（v2.105.0）
2. **已登录**：`gh auth login --hostname github.com --git-protocol https --web`
   - 会给一个一次性验证码，在浏览器输入完成授权
3. **有写权限**：账号需要对 `tanghui2/transcribe-cli` 有 push 权限

## 发布脚本做了什么

| 步骤 | 动作 |
|---|---|
| 1 | 检查工作区干净（不干净就停，不自动提交） |
| 2 | 检查 gh 登录状态 |
| 3 | 检查 `release-assets/` 里的物料齐不齐 |
| 4 | `git push origin main` + 打 tag `v<版本号>` + 推 tag |
| 5 | `gh release create` 并附上两个 zip 与 SHA256SUMS.txt |

版本号从 `desktop/package.json` 读取，不需要手填。

**先干跑一遍看检查结果**：

```bash
python scripts/publish_release.py --dry-run
```

## 物料从哪来

`release-assets/` 里的 zip 是打包产物，不进 git（已在 `.gitignore` 里）。
重新生成：

```bash
# 1. 打后端 exe（Python 侧）
python build_exe.py

# 2. 打桌面版并组装 win-unpacked
python desktop/build_portable.py

# 3. 压成 zip（根目录直接是 exe，解压即用）
cd desktop/dist/win-unpacked
7za a -tzip -mx=7 transcribe-cli-<版本>-windows-x64.zip *

# 4. 复制到 release-assets/ 并算校验值
```

## 手动发布（不想用脚本时）

```bash
# 推源码
git push origin main

# 打 tag
git tag -a v0.2.0 -m "发布 v0.2.0"
git push origin v0.2.0

# 建 Release
gh release create v0.2.0 \
  --title "transcribe-cli v0.2.0" \
  --notes-file release-notes-v0.2.0.md \
  release-assets/transcribe-cli-0.2.0-windows-x64.zip \
  release-assets/transcribe-cli-cli-0.2.0-windows-x64.zip \
  release-assets/SHA256SUMS.txt
```

## 常见问题

**push 卡住不动**

多半是 Git Credential Manager 在等 GUI 授权窗口（有时弹在任务栏看不见）。
最稳的做法是**直接用 gh 的 token 当凭据**：

```bash
gh auth setup-git
```

如果还不行（Git 与 gh 不在同一套安装里时会发生），手动指定：

```bash
git config --global --unset-all credential.helper
git config --global credential.helper \
  '!"C:/Program Files/GitHub CLI/gh.exe" auth git-credential'
```

验证能不能取到凭据：

```bash
printf "protocol=https\nhost=github.com\n\n" | git credential fill
```

能输出 `username=` 和 `password=` 就说明通了。

> 本机实测踩过：git 用的是 PortableGit，而 GCM 装在 `C:\Program Files\Git` 下，
> git 报 `credential-manager-core is not a git command` → 直接改用 gh 的 helper。

**gh 登录报 request_failed**

设备码流程要求 gh 进程持续存活才能在授权后存下 token。
在 IDE/沙箱里跑 `gh auth login` 可能命令一结束就断了，
改成**在真终端里跑**，或把它挂成后台任务等授权完成。

**tag 已存在**

脚本会跳过已存在的 tag，不会报错。需要重新发布同一个版本号时：

```bash
git tag -d v0.2.0
git push origin :refs/tags/v0.2.0
```

**Release 上传 199MB 很慢**

GitHub 单文件上限 2GB，199MB 能传但不快。zip 已用 `-mx=7` 压过，
后端 exe（97MB）是 PyInstaller 产物，本身已压缩，压不动。
